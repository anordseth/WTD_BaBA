# Analysis code

Code for *Cross or bounce? GPS and video data reveal high road encounter rate and altered movement in a common ungulate* (Stemle et al., Movement Ecology).

We applied Barrier Behavior Analysis (BaBA; Xu et al. 2021) to GPS collar data from 125 white-tailed deer at three sites in southern Illinois, 2023–2025, to classify how deer behave when they encounter roads, and paired it with camera collar video from a subset of animals.

## Read this first: what this code does and does not regenerate

This is a **hybrid pipeline**, and knowing that up front will save you confusion.

The original analysis was carried out by the first author. The scripts here are a revised version written for the peer review revision. Some steps regenerate their results from the raw GPS data. Others read derived files produced during the original analysis, because those steps could not be reproduced exactly and rebuilding them would have changed results that the manuscript already reports.

**Regenerated from raw data by this code:**

- Buffer-size sensitivity analysis (`01`) and BaBA encounter classification (`02`), both starting from the already-cleaned GPS track deposited on Dryad (see below)
- Everything downstream of the encounter classification that feeds the main results: the impermeability index and the model (`03`–`04`)
- The chi-square tests comparing video-recorded behavior across encounter types (`05`), reported in the manuscript's Results (χ² values for quick cross vs. bounce, and each against the non-road baseline)

**Some steps are not published here, for different reasons:**

- A per-deer tracking-summary and encounter-rate script only feeds figures and the SI data table — nothing else in this pipeline reads its output. This repository covers the main analyses only, so it's left out along with the rest of the figure/table code.
- The GPS-cleaning script is excluded for a different reason: it produces an input this code reads, not something it regenerates (see below).
- A model-selection script that fit a broader candidate set and ranked by AIC is left out too — `04` already performs its own linear-vs-log AIC comparison internally and selects the winner, so the omitted script was redundant with what's already reproducible from `04` alone.
- A temporal-autocorrelation diagnostic (inter-encounter intervals + a DHARMa/Durbin-Watson check on the main model's residuals) and a standalone SI reference on seasonal twilight duration are left out too — both, like buffer sensitivity and model selection, exist to justify a manuscript claim or modeling assumption rather than produce a primary result, and neither is needed to reproduce anything `01`–`05` already cover.
- The figure script that builds the video-behavior heatmap (Fig. 4) is left out along with the rest of the figure/table code — `05` reproduces the chi-square results the figure displays, not the figure itself.

**Read in as derived inputs, not rebuilt here:**

- The cleaned, analysis-ready GPS track (`GPS_cleaned_analysisset_125animals.csv`) that `01` and `02` take as input. GPS cleaning — duplicate removal, capture-effect and fast-step filtering, then a DOP ≤ 10 filter — was done with a script that is not included in this repository. It's part of the Dryad deposit, so no separate step is needed to obtain it. This file also carries an `AnimalID` column (the D-format ID used elsewhere) so it can be joined directly to the covariates file below without needing any other file.
- The 125-animal analysis set and per-encounter covariates — road category (OSM-based), road density in each deer's home range, land cover proportions within 100 m of each encounter, and their scaled/centered transforms — all in `7_Dryad_Upload/data/road_encounter_covariates.csv`. Script `04` fits its model directly on this file. The land cover extraction was done in ArcGIS Pro over the full dataset; `landcover_extraction_REFERENCE.R` documents the method on one site but is not part of the numbered pipeline and will not run without editing its paths.
- Counts of scored camera-collar video behaviors by encounter type (`7_Dryad_Upload/data/video_behavior_counts.csv`), read directly by `05`. The video review and behavior scoring that produced these counts is not part of this repository, for the same reason as GPS cleaning: it produces an input, not something regenerated by the code here.
- This file is a merge of two files from the original analysis (OSM road-category assignments and a scaled/centered NLCD extraction), joined on `burstID` at deposit time. See the Dryad deposit's README for the merge provenance and column-level verification against the original two-file join.
- Road density (`rdkm_sqkm`, the source of the `std_rdden`/`stdln_rdden` model covariates) — computed once from each deer's 95% kernel density home range and the road network, in a script that was never made self-contained (it depends on interactive session state and home-range shapefiles that were never saved) and is not included here. The value is not independently re-derivable from what's in this repository or the Dryad deposit.

So `02` reproduces the encounter classification from an already-cleaned GPS track, and everything downstream of it reproduces in turn, while the GPS cleaning step and the modelling covariates are read in as files rather than being built by the chain above them.

`01` (buffer sensitivity) is numbered before `02` (BaBA classification) because it justifies the 50 m buffer that `02` then uses — it doesn't read `02`'s output, so it can run first or in any order relative to it.

**Numbering note:** these numbers are specific to this repository and don't necessarily match any internal working-copy numbering referenced in code comments or commit history — they're renumbered here to run continuously with no gaps, since several steps (GPS cleaning, tracking summaries, and others) aren't published at all.

## Setup

1. Clone this repository. Paths are resolved with the `here` package relative to the repository root (via its `.git` folder), so scripts work regardless of your working directory — no `.Rproj` file is required, though opening the folder as an RStudio project also works.
2. Download the data deposit from Dryad (https://doi.org/10.5061/dryad.51c59zwr4) and place the three files this code reads in a `7_Dryad_Upload/data/` folder at the root of this repository: `GPS_cleaned_analysisset_125animals.csv`, `road_encounter_covariates.csv`, and `video_behavior_counts.csv`.
3. Create an empty `1_Data/revisions/` folder at the repository root — this is where every script writes its output.
4. Prepare the road network layer (see "Spatial data setup" below) and place it at `1_Data/leyna_data/spatial/` — needed by scripts `01`, `02`, and `03`.

### Spatial data setup

The road network used in `01`, `02`, and `03` is not included in this repository or the Dryad deposit — it's an extract of the public [USGS National Transportation Dataset](https://www.usgs.gov/programs/national-geospatial-program/national-transportation-dataset-ntd) (The National Map), which we merged and reprojected rather than modified, so we point to the source instead of redistributing a copy.

To reproduce the road layer these scripts expect:

1. Download road/transportation features from the USGS National Transportation Dataset (via [The National Map downloader](https://apps.nationalmap.gov/downloader/)) for the study region: southern Illinois, covering both the Shelbyville, IL area (~39.5°N) and the Touch of Nature / SIU-Carbondale area (~37.6–37.7°N).
2. Reproject to UTM Zone 16N (EPSG:32616).
3. Split (or download separately) into two layers matching the scripts' expected filenames: `Trans_Road_Nroadsutm.shp` (covers Shelbyville/LSV) and `Trans_Road_Sroadsutm.shp` (covers Touch of Nature/TON and SIU), and place both (with their `.dbf`/`.prj`/`.shx`/`.cpg` sidecar files) in `1_Data/leyna_data/spatial/`.

The attribute fields the scripts rely on are the standard NTD schema (`permanent_`, `mtfcc_code`, `tnmfrc`, etc.) — no custom attributes are required.

## Running the code

Run the numbered scripts `01`–`05` in order. Each reads from `7_Dryad_Upload/data/` or `1_Data/revisions/` (a Dryad file, or a previous script's output) and writes to `1_Data/revisions/`.

This repository covers the main analyses only — the scripts that generate the manuscript's figures and formatted tables are not included here.

## Pipeline

| Script | What it does | Reads | Writes |
|---|---|---|---|
| `01_buffer_sensitivity.R` | Re-runs encounter detection over 20–80 m buffers to justify the 50 m choice used in `02` | `GPS_cleaned_analysisset_125animals.csv`, roads | `buffer_sensitivity_results.csv` |
| `02_baba_classify_encounters.R` | Runs BaBA: finds road encounters and assigns each a behavioral category | `GPS_cleaned_analysisset_125animals.csv`, road polylines | `BaBA_all_AEN.Rdata`, per-site BaBA files |
| `03_impermeability_index.R` | Impermeability index per 2 km road segment | `02`, roads | `Rank_{site}_AEN.rds`, `allrank_AEN.csv` |
| `04_logistic_model.R` | Mixed-effects logistic regression of quick cross vs. bounce, with an internal linear-vs-log AIC comparison, DHARMa, and collinearity checks | `road_encounter_covariates.csv` | Model object, diagnostics |
| `05_video_behavior_chisq.R` | Chi-square tests comparing video-recorded behavior between quick cross, bounce, and the non-road baseline | `video_behavior_counts.csv` | `video_behavior_chisq_results.csv` |

## Encounter categories

BaBA assigns each encounter one of seven categories, grouped here as:

- **Unaltered (crossing):** quick cross, average movement
- **Altered (non-crossing):** bounce, trace, back-and-forth, trapped
- **Unclassified:** unknown

"Trapped" does not mean physical confinement. It means the deer stayed near the road for a prolonged period (≥ 36 h), whether or not the road was the reason.

The impermeability index in `03` is the fraction of a segment's encounters that fell in the altered group, from 0 (every encounter crossed) to 1 (none did). It is an unweighted proportion and is not rescaled within site, so values are comparable across sites.

## Key BaBA parameters

Buffer 50 m, short interaction 4 h, prolonged interaction 36 h, straightness window 7 days, `max_cross = 2`. Encounters with more than two crossings are reclassified as unknown to absorb GPS error (~10–12 m) and road polyline inaccuracy.

## Data

Data needed to run this pipeline (GPS and encounter covariates) are deposited on Dryad rather than distributed with this repository, because of file size: https://doi.org/10.5061/dryad.51c59zwr4. See the Dryad deposit's own README for the file list and column dictionary, and for what was intentionally excluded (road network shapefile, NLCD raster — cite USGS sources instead; video behavioral data; reproducible pipeline outputs).
